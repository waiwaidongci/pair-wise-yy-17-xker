# 凝结水样链与沉积速率复核台

围绕凝结水瓶号建立采样—送检—复核—归还样单链，并按规则自动判定沉积速率。

## 启动

```bash
npm install
npm start
```

默认地址：http://localhost:3912 ，数据保存在 `data/db.json`。

## 分层结构（规则 / 存储 / 页面分开）

- `lib/rules.js`：**规则层**。全部阈值与判定（顶空一成、校准半小时、基准偏离 5%、
  速率负增长 / 降幅两成、换人录入、封条比对、结论失效与旧版留档），纯函数不碰数据库。
- `lib/storage.js`：**存储层**。只管 `db.json` 读写，并用进程内写锁把「读—改—写」串行化，
  保证并发登记同一瓶号时只有第一份样单生效。
- `project.config.js`：**页面层配置**。标题、看板、统计、表单字段、卡片动作与弹窗，
  不包含任何阈值判定。
- `public/`：页面资源（读取配置渲染列表、统计、履历与动作弹窗）。
- `server.js`：**路由层**。只做参数校验与「存储 + 规则」编排。

## 业务规则

1. 同一瓶号归还前只能有一份未结束样单；重复或并发登记直接沿用首次结果（返回 `reused`）。
2. 采样质控：顶空占比 > 10%、校准距采集 > 30 分钟、读数偏离基准 > 5%，转「待重采」。
3. 送检录入须由非采集人填写送检封条号与沉积质量。
4. 沉积速率 = 沉积质量 ÷（采集时刻 − 布放时刻，小时）。速率负增长（≤ 0）、
   较同点上一已归还瓶下降幅 > 20%、或采集/送检封条不符，进「待复核」。
5. 基准、沉积质量或采集 / 布放时刻变更：旧结论立即失效并重新计算，旧版写入 `versions` 留档；
   列表、统计和履历随同一数据源一致刷新。

## 状态流

`待重采`（重采样登记）→ `采样合格`（送检录入）→ `已完成` / `待复核`
（复核通过）→ `已完成`（归还瓶号）→ `已归还`（瓶号可重新启用）。
